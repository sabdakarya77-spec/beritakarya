## 🔑 Key Features

### ✅ Multi-Tenancy
- **Site-based isolation** via `siteId` foreign keys
- All major tables scoped to site: User, Article, Category, Advertisement, Comment, Media, PageView, Notification, AuditLog, AIUsage, KYCViewLog
- Queries **must** filter by `siteId` for data isolation

**Example:**
```typescript
// Correct: Scoped by site
const articles = await prisma.article.findMany({
  where: { siteId: user.siteId }
})

// Wrong: No site filter (data leak!)
const articles = await prisma.article.findMany() // ❌
```

---

### ✅ Soft Delete Pattern
Implemented on critical models:

| Model | Field | Indexed |
|-------|-------|---------|
| Site | deletedAt (DateTime?) | ✅ Site_deletedAt_idx |
| User | deletedAt (DateTime?) | ✅ User_deletedAt_idx |
| Article | deletedAt (DateTime?) | ✅ Article_deletedAt_idx |
| Category | deletedAt (DateTime?) | ✅ Category_deletedAt_idx |

**Query active records only:**
```typescript
const activeUsers = await prisma.user.findMany({
  where: { deletedAt: null }
})
```

## 🔄 Migration Workflow

### 1. Make Schema Changes
Edit `apps/api/prisma/schema.prisma`

### 2. Generate Migration
```bash
pnpm prisma migrate dev --name descriptive_name
# OR use custom script:
node generate-migration.js
```

### 3. Review Generated SQL
Check `prisma/migrations/YYYYMMDDHHMMSS_descriptive_name/migration.sql`

### 4. Test Locally
```bash
pnpm prisma migrate dev  # Applies to local DB
pnpm prisma studio      # Verify changes
```

### 5. Commit Migration
```bash
git add prisma/migrations/
git commit -m "feat: add [feature description]"
```

### 6. Deploy to Production
```bash
# On production server
pnpm prisma migrate deploy
pnpm prisma generate
```

---

### Slow Query Monitoring

Enable `pg_stat_statements` extension:
```sql
CREATE EXTENSION IF NOT EXISTS pg_stat_statements;
```

Query slowest queries:
```sql
SELECT query, calls, total_time, mean_time, rows
FROM pg_stat_statements
ORDER BY total_time DESC
LIMIT 20;
```

## 🔐 Security Considerations

### Multi-Tenancy Isolation
**Critical:** Always filter queries by `siteId`!

**Use middleware to enforce:**
```typescript
// In API routes with site context
const siteId = req.headers['x-site-id'] as string
const data = await prisma.article.findMany({
  where: { siteId } // Always filter!
})
```

---

### Soft Delete vs Hard Delete
- Use **soft delete** (`deletedAt`) for User, Article, Category, Site
- Allows recovery and GDPR compliance
- Hard delete (`DELETE`) only for temporary/log tables

---

### AI Quota Enforcement
- Middleware: `apps/api/src/middleware/aiQuota.ts`
- Redis counters for performance
- 80% warning threshold
- Automatic disable at 100%

## 🗄️ Backup Strategy

### Automated Backups
Script: `infra/scripts/backup-database.sh`

**Schedule:** Daily at 2 AM via cron
```bash
0 2 * * * /opt/beritakarya/infra/scripts/backup-database.sh
```

**Retention:** 7 days (auto-cleanup)

**Location:** `/opt/beritakarya/backups/`

**Filename format:** `beritakarya_prod_YYYYMMDD_HHMMSS.sql.gz`

---

### Manual Backup
```bash
# Backup
pg_dump -U beritakarya beritakarya_prod | gzip > backup.sql.gz

# Restore
gunzip -c backup.sql.gz | psql -U beritakarya beritakarya_prod
```

---

### Test Restore Procedure (Monthly)
1. Create test database: `createdb beritakarya_test`
2. Restore backup: `gunzip -c backup.sql.gz | psql -U beritakarya beritakarya_test`
3. Verify data integrity
4. Drop test database: `dropdb beritakarya_test`

## 📝 Naming Conventions

### Tables
- PascalCase: `Site`, `User`, `Article`
- No pluralization (singular)
- Match model names in schema

### Columns
- camelCase: `createdAt`, `updatedAt`, `deletedAt`
- Foreign keys: `${model}Id` (e.g., `siteId`, `userId`)
- Unique constraints: snake_case (Prisma `@unique`)

### Indexes
- Pattern: `"TableName_columnName_idx"`
- Composite: `"TableName_col1_col2_idx"`
- Example: `"Article_siteId_status_idx"`

## 🆘 Common Issues

### Migration Already Applied
```
Error: P3005
```
**Fix:** Migration already in `_prisma_migrations`. Check status:
```bash
pnpm prisma migrate status
```

---

### Connection Pool Exhausted
```
Error: P2025: Connection pool is full
```
**Fix:** Increase pool size or close connections properly:
```typescript
// Always disconnect Prisma on app shutdown
await prisma.$disconnect()
```

---

### Column Not Found After Migration
Migration applied but column missing.

**Fix:** Check migration order. Rollback and reapply:
```bash
pnpm prisma migrate resolve --rolled-back "migration_name"
pnpm prisma migrate deploy
```
